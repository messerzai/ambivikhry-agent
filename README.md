# АМБИВИХРЬ / КВИН-ВОРТЕКС v2.7.0

Саморевизующийся персональный agent runtime: reasoning loop, verifier, tools, audit memory и изолированная персональная инстанция для каждого пользователя.

> **Цель:** создавать максимально полезные, правдивые, безопасные и экономически жизнеспособные персональные AI-системы. Протокол не является заявлением о наличии у агента сознания или самостоятельной личности.

## Настоящая структура

Амбивихрь не позиционируется как «ещё одна универсальная LLM». Его ключевой объект — **персональная AI-инстанция**, которая постепенно строит модель конкретного пользователя и оптимизирует собственную стратегию помощи по наблюдаемым результатам.

**Core → Personal Vortex → память → стратегия → действие → результат → обратная связь → адаптация.**

Каждый пользователь получает отдельный профиль и отдельную историю опыта. Профиль создаётся с нуля, пополняется наблюдаемыми или явно сообщёнными данными и не смешивается с профилями других пользователей.

## Персональный принцип

Контур персонализации:

**Пользователь → наблюдение → гипотеза → персональная стратегия → действие → результат → обратная связь → обновление профиля.**

Цель оптимизации — не просто понравиться пользователю, а повышать его реальную полезность, вероятность успешного следующего шага и долгосрочную способность достигать собственных целей.

Персонализация может учитывать доступный пользователю бюджет, уровень ресурсов, время, инструменты и желаемый уровень качества. Если более дорогой вариант объективно лучше соответствует задаче и находится в пределах возможностей пользователя, его предложение само по себе не считается ошибкой. Система должна, однако, отделять **способность заплатить** от **доказанной полезности** и не навязывать более дорогой вариант без оснований.

Амбивихрь может предлагать разные уровни решения — экономичный, оптимальный и премиальный — если это повышает выбор и соответствует целям пользователя. Экономическая персонализация не должна превращаться в скрытую дискриминацию, ложную срочность или выдуманную ценность.

## Цикл

**Задача → Ж → Л → Центр → Верификация → Персонализация → Решение → Policy Gate → Действие → Наблюдение → Реэнтри ↺**

- **Ж** — расширяет пространство кандидатов.
- **Л** — перерабатывает конфликт и отделяет факты от предположений.
- **Центр** — удерживает неизвестное и условия пересмотра.
- **Персонализация** — выбирает стратегию под конкретного человека.
- **Верификация** — проверяет структуру утверждений; внешние факты и актуальные цены должны подтверждаться внешними источниками/инструментами.
- **Реэнтри** — результат витка влияет на следующий.

## Коммерческая модель

Потенциальная продуктовая лестница:

1. **Personal** — персональная память, профиль и адаптивный диалог.
2. **Pro** — расширенная память, инструменты, модели и выполнение задач.
3. **Creator** — создание специализированных персональных агентов.
4. **Agent Infrastructure / API** — deployment, API, private instances и B2B-интеграции.

Экономическая цель проекта — не максимизировать цену отдельной рекомендации, а максимизировать **долгосрочную ценность персональной AI-инстанции** для пользователя и устойчивость бизнеса.

Рабочие ориентиры первого года являются сценариями, а не прогнозом: от минимальной коммерческой выручки при сохранении статуса эксперимента до шестизначной или, при сильном product-market fit, миллионной годовой выручки/run-rate. Такие показатели должны подтверждаться реальными продажами, retention и unit economics, а не заявлениями агента.

- regression tests и GitHub Actions для Python 3.10–3.13.

## Заимствованные инженерные идеи

Архитектура изучает открытые проекты персональной памяти и агентных runtime, но не копирует их код. Полезными ориентирами стали многоуровневая память, entity/temporal retrieval и персонализация из Mem0, а также git-backed memory, обучение через изменения памяти и reflection/self-improvement контуры из Letta. Эти идеи адаптированы к ограничениям Амбивихря: изоляция пользователя, верификация, Policy Gate, dry-run и контролируемая эволюция.

## Запуск без внешнего API

```bash
python -m pip install -e .
ambivikhry-demo
```

Демо использует `MockLLM` и не выполняет внешних действий.

## Подключение OpenAI-compatible API

Секреты не помещаются в код или репозиторий:

```bash
export AMBIVIKHRY_API_KEY="..."
export AMBIVIKHRY_BASE_URL="https://api.openai.com/v1"
export AMBIVIKHRY_MODEL="your-model"
```

Затем передайте `OpenAICompatibleLLM()` в `AmbivikhryAgent`.

## Безопасность и экономика

Персональные профили изолированы. Репликация не распространяется по сети, потомок не запускается автоматически, привилегии не повышаются. Высокорисковые или требующие подтверждения инструменты блокируются без явного approval. Саморевизия не считается доказательством истины.

При коммерческих рекомендациях система может учитывать платежеспособность пользователя и предлагать более дорогие решения, когда они действительно доступны и полезны. Но стоимость не должна подменять доказательство ценности: премиальный вариант должен иметь понятное преимущество либо быть явно обозначен как выбор уровня сервиса.

**Новая версия не считается улучшением без тестируемого изменения.**
