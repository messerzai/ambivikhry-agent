# Visual Facets — грань самости

## Идея

Каждый диалог оставляет не «портрет личности», а мозаику наблюдаемых паттернов: темы, повторяемость, напряжение, открытость, направление интереса, способы связывать идеи. Visual Facet Renderer превращает эту мозаику в **глубокую графическую грань**.

Грань должна быть:

- индивидуальной;
- воспроизводимой для одного и того же состояния данных;
- изменяемой при появлении новых паттернов;
- объяснимой через входные паттерны;
- пригодной как SVG-артефакт и как conditioning/prompt input для будущего image-model слоя.

Это художественная визуализация наблюдаемой модели, а не диагностика человека и не доказательство его «истинной сущности».

## Архитектура

`dialogue → pattern mosaic → weighted facet state → visual facet → SVG → optional image model`

Внутренний renderer не зависит от внешнего генератора. Это позволяет сначала получить дешёвую локальную грань, а затем подключить более мощную модель.

### Внешний research

Исследованы:

- **ComfyUI** — модульный node/graph подход и API workflow; полезная архитектурная идея для будущего графа визуальных преобразований. Не копируем GPL-код в proprietary core. citehttps://github.com/Comfy-Org/ComfyUI
- **Transformers.js** — локальные embeddings и inference в браузере; полезно для будущего semantic pattern extractor. Код не копируется в core. citehttps://github.com/huggingface/transformers.js
- **Kandinsky 5** — открытая линия text/image/video generation и ComfyUI workflow; потенциальный внешний backend для художественного слоя. citehttps://github.com/kandinskylab/kandinsky-5

Лицензии этих проектов проверяются отдельно перед любым прямым включением кода. Сейчас используется собственная реализация renderer.

## Эволюция

Следующие витки должны тестировать не «красивее», а:

1. лучшее соответствие паттернам;
2. устойчивость визуального ядра при малых изменениях диалога;
3. заметную эволюцию при появлении новых устойчивых паттернов;
4. возможность обратного чтения: какие паттерны породили какую грань;
5. сохранение lineage: состояние → facet seed → SVG → image-model workflow.

Будущий image-model adapter должен принимать структурированный `VisualFacet`, а не сырой приватный диалог. Это уменьшает утечку персональных данных и делает художественную генерацию отделённым слоем.
