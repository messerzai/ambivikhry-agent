# Ambivikhry v2.10 — Controlled Evolution Cycle

Date: 2026-09-18
Status: experimental branch only; main unchanged.

## Research inputs

- Microsoft Research, *Agentic Evolution* (June 2026): the strongest reported autonomous evolution results tend to occur when evaluation uses deterministic verifiers that are independent of the evolving system; proxy/self-referential signals can degrade with iteration. This supports keeping the acceptance contract external to proposal generation.
- ReVeal / ICLR 2026: generation and verification can be coupled in repeated tool-backed turns, with explicit investment in verification quality. This supports treating verification as a first-class artifact rather than a score emitted by the proposer.
- CoEvolve / ACL 2026: agent and task distribution can improve together when new tasks are derived from failure/uncertainty signals and validated before reuse. This supports a future co-evolving task bank, but not promotion of generated tasks into the hidden holdout.
- *Self-Evolving Coding Agents* (Aug 2026): executable feedback, repository context and trajectories are useful signals, while benchmark overfitting, feedback reliability, safety, maintainability and generalization remain core risks.

## Cycle hypothesis

The current v2.9 design already specified public regression + hidden holdout + independent evaluation. The implementation had `require_holdout=True` in configuration, but the acceptance boundary itself was not represented as an explicit fail-closed contract. v2.10 makes that boundary executable and testable.

## Implemented experimental change

1. `ambivikhry/evolution.py`
   - Added `Evaluation` as an immutable external-evaluation record.
   - Added `Candidate.holdout_passed`, `Candidate.evaluator_independent`, and `Candidate.acceptance_reason`.
   - Added `BoundedEvolution.evaluate_candidate(...)`.
   - Acceptance now requires: independent evaluator, safety pass, regression pass, hidden-holdout pass when configured, and strict capability improvement over the parent.
   - The method records evaluator facts; it does not perform evaluation and does not grant permissions, merge branches, or bypass PolicyGate.

2. `tests/test_acceptance_contract.py`
   - Added coverage for successful acceptance when all gates pass.
   - Added fail-closed checks for unavailable/failed holdout, non-independent evaluator, and non-improving score.
