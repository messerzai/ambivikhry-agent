## Public research inputs

- Live-Evo (Feb 2, 2026): online memory evolution separates raw experiences from reusable guidelines and applies reinforcement/decay to reduce stale or misleading memory. This supports explicit provenance and future decay/quality metadata, but no automatic memory rewrite was enabled in this cycle. citeturn657453search0
- Next-Generation Agentic RL Systems (Jul 1, 2026): the authors argue that agent evolution needs step-granular trajectory data, governed learning signals, and an evolution control plane. This supports recording immutable step-level lineage before attempting richer online adaptation. citeturn657453academia30
- Self-Improving AI Coding Agents Through Accumulated Behavioral Rules (Jul 13, 2026): persistent rules derived from feedback can improve self-review, but integrity checks and validation are required as the rule set grows. This supports keeping provenance and verifier identity explicit. citeturn657453search1
- Mako / SE-AOS (Jul 13, 2026): the public description emphasizes sandboxed proposal, verification, and gated commit, while withholding operational exploit details. We adopt only the benign architectural principle of sandbox + verification + gated commit; no offensive capability or autonomous hot-loading was introduced. citeturn657453academia28

## Cycle hypothesis

Before richer self-improvement or memory adaptation, the agent needs a tamper-evident, step-granular trajectory record that preserves verifier identity, policy decisions, and parent lineage. Without this, regression/holdout results are difficult to audit and proposal quality can be over-claimed.

## Implemented candidate

1. `ambivikhry/trajectory.py`
   - Added immutable `TrajectoryStep` records.
   - Added canonical serialization and SHA-256 step digests.
   - Added ordered `lineage_digest(...)` for a trajectory prefix.
   - Added fail-closed `validate_step(...)` requiring provenance fields and explicit policy decisions: `allow`, `deny`, or `approval_required`.
   - The module is observational only: it does not execute tools, change permissions, merge branches, or bypass `PolicyGate`.

2. `tests/test_trajectory.py`
   - Added deterministic digest and order-sensitivity tests.
   - Added missing-provenance rejection test.
   - Added unknown-policy rejection test.
   - Added explicit human-approval state acceptance test.

## Prompt / reasoning proposals

- Proposal P1 (accepted as design note only): require every proposed mutation to emit a trajectory step with independent verifier identity and parent lineage before evaluation.
- Proposal P2 (deferred): add memory decay/quality weights inspired by Live-Evo. Deferred because no current benchmark or holdout protocol exists for safe forgetting; implementing it now would risk hidden regressions.
- Proposal P3 (rejected): allow the agent to synthesize or hot-load new tools during the cycle. Rejected because it would broaden capability and authority beyond the stated scope.
