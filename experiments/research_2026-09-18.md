# Research intake — 2026-09-18

## High-value findings

### ReVeal (ICLR 2026)
Self-verification can be treated as a first-class optimization target. The useful pattern for Ambivikhry is generation ↔ verification co-evolution with tool feedback, rather than reflection alone.

### EvoTest (ICLR 2026)
An Actor and an Evolver can be separated. The Evolver analyzes traces and proposes changes to prompts, memory, hyperparameters and tool routines. This maps directly to Ambivikhry's helper-council design.

### HyperAgents (Meta, 2026)
A task agent and a meta-agent can co-evolve inside an editable program. Useful architectural idea: explicitly represent the improvement process as an object that itself can be evaluated. Constraint: retain independent evaluation and policy boundaries.

### Self-Evolving Coding Agents (2026 survey)
Executable feedback, repository context and coding trajectories are strong signals for software-agent evolution. Major risks include benchmark overfitting, unreliable feedback, maintainability and safety.

### A Self-Improving Coding Agent (2025)
Self-editing plus reflection can materially improve coding-agent benchmarks. This supports experimenting with self-edit proposals, but not treating self-reported improvement as proof.

### Current caution
Recent reporting and research discussion emphasize that recursive self-improvement becomes risky when evaluation, monitoring or safety controls can be modified by the system being evaluated. Therefore the experimental architecture keeps independent safety/evaluation boundaries immutable from candidate agents.

## Imported principles

1. Generate multiple candidates.
2. Separate actor from evolver.
3. Co-evolve tests only against fixed external checks.
4. Preserve failed candidates and lineage.
5. Use holdout evaluations to reduce benchmark overfitting.
6. Require measurable improvement before consolidation.
